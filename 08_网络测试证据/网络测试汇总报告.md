## 1. 抓取方法（可复现）

### 1.1 手段一：netstat 全系统采样

每 5 秒执行一次 `netstat -ano`，提取所有**非内网** TCP 连接
（排除 `127.*`、`10.*`、`192.168.*`、`172.16-31.*`、`224.*`、`239.*`），
把 PID 映射为进程名后写入 CSV：`ts,pid,process,local,remote,state`。

脚本：`run1_4h_netstat/orchestrator.ps1`、`run3_1h_pktmon/orchestrator.ps1`

### 1.2 手段二：pktmon 包头抓取

```
pktmon filter remove *
pktmon filter add SYNs -t TCP SYN
pktmon filter add UDPs -t UDP
pktmon start --capture --pkt-size 512 --file-name cap.etl --file-size 256 --log-mode multi-file
# ... 抓取结束 ...
pktmon stop
pktmon etl2txt cap.etl --out cap.txt --brief --timestamp
```

- 过滤 `TCP SYN` + `UDP`，512 字节包头（含 TCP/UDP 端口与 DNS 查询），
  相比全量抓包体积降低约 4 个数量级（4h 约 380KB），可安全长时间运行。
- 转换后的文本：`run2_pktmon/pktmon_capture.txt`、`run3_1h_pktmon/pktmon_capture.txt`

### 1.3 辅助记录

| 文件 | 内容 |
|---|---|
| `*/dns.log` | 每 5 分钟 DNS 缓存快照（`时间|域名|IP|状态`） |
| `*/procs.log` | 每 5 分钟搜狗进程清单（PID/名称/路径） |
| `*/typing.log` | 每轮 IME 组合打字记录（`round N : typed [中文]`） |
| `*/status.txt` | 编排器运行状态（启动/采样/停止） |

### 3.1 需要说明的 3 个「搜狗段」命中

文档 §9.4 给出的经验性搜狗/腾讯段清单（`116.130/16`、`123.125/16`、`220.194/16` 等）
在本轮命中 3 个地址。逐一溯源后**均非搜狗进程发起**：

| 目标 IP | 端口 | 实际发起进程 | 归属（APNIC RDAP 权威） |
|---|---|---|---|
| 116.130.230.115 | 80 | `Widgets.exe`（Windows 资讯小组件） | 中国联通 `116.128.0.0/10` |
| 116.130.224.118 | 80 | `msedge.exe` | 中国联通 `116.128.0.0/10` |
| 220.194.72.190 | 80 | `svchost.exe` = **CryptSvc**（Windows 加密服务） | 中国联通 `220.192.0.0/12` |

> **重要更正**：`116.130.0.0/16`、`220.194.0.0/16` 经 APNIC RDAP 查询确认是
> **中国联通（China Unicom）** 的 ISP 分配段，并非搜狗专属。早期文档中的
> 「搜狗/百度CDN」分类是启发式猜测，会把联通段内的任意主机误判为搜狗。
> 判定搜狗是否联网，应以**发起进程**为准，而非仅看目标 IP 段。

CryptSvc（PID 3300）已确认**未加载任何搜狗模块**（全进程模块扫描），
其外连属系统证书/CRL 类取用。

## 5. 最终结论

| 判定项 | 结果 |
|---|---|
| 搜狗进程主动建立的公网 TCP 连接 | **0 条**（四次测试合计约 8.5 小时） |
| 搜狗进程 UDP 外发端点 | **0 个** |
| IME 核心注入宿主后的 push 长连接 | **无** |
| 通过 hosts / 防火墙实现的「伪断网」 | **无**（hosts 0 条、防火墙未动） |
| 断网实现方式 | **原生**：scrub 去公网字面量 + 5 模块 `.nblk` IAT 钩子 + 注册表应用配置 |
| 中文输入（真实 IME 组合） | **正常**（run1 862 轮、run3 224 轮、run4 224 轮全部出中文） |

**验收结论：搜狗输入法 16.8 断网绿化版（cangshui）「原生断网」项通过。**
